# Media Speed HUD — 网页媒体倍速调节 Chrome 扩展

快捷键调节网页视频 / 音频播放速度，调节时在**视频左上角**短暂出现一个带过渡动画的速度提示框；新视频默认 1×，看过的视频自动沿用它上次的倍速。

```
media-speed-hud/
├── manifest.json      MV3 清单
├── background.js      Service Worker（工具栏徽标显示当前速度）
├── content.js         核心：快捷键、速度控制、按视频记忆、提示框
├── content.css        提示框样式（出现 / 消失 / 连续按键弹跳动画）
├── popup.html|css|js  工具栏弹窗（滑块、预设、页面开关）
├── options.html|css|js设置页（改键、范围、动画、记忆管理）
└── icons/             扩展图标
```

---

## 一、安装（3 分钟）

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择 `media-speed-hud` 文件夹
4. （可选）`chrome://extensions/shortcuts` 里给扩展本身分配快捷键；本扩展的倍速键在页面内直接生效，无需在此配置

> Chrome 版本要求：102 及以上（建议 110+，`backdrop-filter` 等视觉效果更完整）。

---

## 二、默认快捷键

| 按键 | 作用 |
|---|---|
| `1` | 复原 1× |
| `2` | 2 倍速 |
| `5` | 1.5 倍速 |
| `-` | 减 0.1 |
| `=`（或 `Shift + =` 即 `+`） | 加 0.1 |

- 小键盘同样有效：`Numpad1 / 2 / 5 / - / +`
- `Ctrl` `Alt` `Meta` 组合键**永不劫持**，`Esc`、方向键、空格、`J K L` 等站点按键不受影响
- 在输入框、评论框、`contenteditable` 区域打字时不劫持按键
- 页面上没有可控制媒体时，按键**完全放行**给站点

## 三、速度提示框

- **尺寸**：`width:max-content` 紧贴文字（无多余空白），`padding:6px 9px 7px`，圆角 9px，`max-width:220px`；
  速度条用 `align-self:stretch` 跟随卡片宽度（旧版用 `width:100%` 会把卡片撑宽、右侧出现空白，已修正）
- **位置**：当前视频**左上角**内缩 10px（`fixed` 定位，不受播放器容器 `overflow:hidden` 影响）
- **背景透明度可调**：设置项 `hudAlpha` 0.15–1，**默认 0.55**（旧版是 0.86/0.80，明显更透气），在设置页拖滑杆
- **整体大小可调**：设置项 `hudSize` 0.6–1.8（默认 1），与“随视频自适应”叠加，最终缩放限制在 0.5–2
- **动画**：`opacity + translateY(-9px) + scale(0.88 → 1)`，缓动 `cubic-bezier(.16,1.02,.3,1)`（轻微回弹），连续按键时额外播放一次 240ms 弹跳
- 自动隐藏：默认停留 1200ms（记忆恢复提示 2000ms），消失动画 180ms
- **内容**：`▲ 1.2×` + 说明（`+0.1` / `已恢复上次速度`）+ 底部速度条
- **配色随操作方向**：加速绿 `#3fd39b`、减速橙 `#ffb35c`、复原蓝 `#8ab4ff`、记忆恢复紫 `#c39bff`
- 尺寸随视频自适应缩放（0.8×–1.25×），`prefers-reduced-motion` 时自动取消动画
- 页面切换、视频滚出屏幕时立即隐藏，不会残留
- **全屏也可见**（v1.2.0 修正）：监听 `fullscreenchange`（含 webkit / MS 前缀）后把 HUD 重新挂到
  `document.fullscreenElement` 内部（B 站等把播放器容器 `requestFullscreen` 的站点以前看不到，现在正常）；
  坐标基准同时换成该全屏元素的左上角

## 四、按视频记忆速度

| 场景 | 行为 |
|---|---|
| 打开一个全新视频 | 默认 **1×** |
| 重新打开看过的视频 | 自动恢复上次倍速，并短暂显示 `↺ 已恢复上次速度` |
| 同一标签页内 SPA 切换到另一个视频（YouTube/B站连播） | 新视频回到 1×，已记忆的自动恢复 |
| 用站点自带的倍速菜单 | 扩展会**采纳并记忆**该速度，保持一致 |

记忆键（`mediaKey()`）：

- 有真实视频地址（`http/https/file`）→ `域名 + 路径`，**忽略查询参数**（签名、时间戳、`?start=` 都不会让记忆失效）
- `blob:` / MediaSource（YouTube、B 站等）→ `域名 + 视频 ID + 时长`
  - YouTube：`watch?v=` / `/shorts/` / `/embed/` / `/live/` 里的 ID
  - Bilibili：`BV…` / `av…` + 分 P
  - 其他站点：常见 `?v= / ?videoId= / ?id=` 参数或 `pathname`
- 记忆存 `chrome.storage.local`，**默认只保留最近 30 天用过的**，另有 1200 条上限按最近使用时间淘汰；跨设备同步的是**设置**，速度记忆留在本机

### 记忆会不会越占越大、把电脑卡住？

不会构成实际负担，量级如下：

| 项目 | 实际数值 |
|---|---|
| 单条记忆 | 约 100–160 字节（一个 key + `{rate, ts}`） |
| 1200 条（上限） | 约 130–190 KB |
| `storage.local` 配额 | **10 MB**（离满还差 50 倍以上） |
| 清理时机 | Service Worker 每次唤醒 / 内容脚本启动 / 每次写入 / 改保留期时 |

真正值得关注的是**页面里重复扫 DOM 的成本**，已做两点优化：

1. **媒体注册表 `registry`**：扫描时增量维护已知媒体列表，按键时直接读列表，不再每次重扫整页
2. **穿透 shadow DOM 的深度扫描每 4 次轮询才做一次**（约 6 秒一次），平时只取 `video,audio`，大页面开销明显下降

设置页「播放速度记忆」卡片会直接显示 **当前占用 KB、条目数、保留期**，可选 7 / 30 / 90 / 180 天或永久保留。

## 五、弹窗与设置页

**弹窗**（v1.2.0 精简为两个模块，整窗毛玻璃质感：底层柔光斑 + 面板 `backdrop-filter`）：

1. **当前速度**：大数字 + 滑块（0.05 步进）+ `−/+` 一档 + 1× / 1.5× / 2× 快捷 + 常用预设行
2. **在本页禁用快捷键**：开关（写入站点例外名单）

其余全部设置放到设置页（右上角 ⚙），弹窗不再堆砌开关。

**设置页**（扩展详情 → 扩展设置，或弹窗右上角 ⚙）：

- ⌨️ 改键：点「按下按键…」再按一个键即可记录，可增删预设、恢复默认
- 🎚 速度范围：微调幅度 0.05–1、最低 0.05–1、最高 1–16、是否控制纯音频
- ✨ 提示框：停留时长、**背景不透明度 0.15–1**、**整体大小 0.6–1.8**、速度条、说明文字、随视频缩放
- 🧠 记忆：**保留期 7 / 30 / 90 / 180 天 / 永久**（改完立即执行一次淘汰）、自动恢复、新视频强制 1×、清空 / 导出 / 导入 JSON
- 🚫 站点例外：加域名后该站快捷键完全交还给站点
- 📚 记忆概况：一行显示条目数 + 占用 KB + 保留期（明细列表已删除，避免 UI 臃肿）

## 六、实现要点（为什么这样写）

1. **快捷键捕获在 `window/document` 的 capture 阶段** + `stopPropagation()`：
   YouTube 等站点把 `1/2/5` 用作跳转 10%/20%/50%，capture 拦截保证扩展优先；
   把接管方式改成「与站点共享按键」即可恢复站点行为。
2. **每个 frame 独立注入（`all_frames: true`）**：键盘事件只派发到当前焦点 frame，
   所以内嵌播放器（iframe）里的视频也能被正确控制。
3. **“当前视频”的判定顺序**：画中画 > 元素获焦 > 鼠标悬停 > 正在播放 > 面积最大；
   小于 100×70 的静音暂停预览视频（新闻页自动播放小窗）不抢占键盘。
4. **`loadstart / loadedmetadata / durationchange` + MutationObserver + 1.6s 兜底轮询**：
   SPA 换视频时 `<video>` 元素不变、只换 `src`，靠“媒体身份键”变化来识别新视频。
5. **媒体注册表 + 间隔性深度扇描 + 后台标签页零开销**：轻扫只取 `video,audio`，每 4 次才穿透一次 open shadow DOM
   （深度上限 4 层、访问上限 6000 节点）；`document.hidden` 时 `scan()` 直接返回，后台标签页不做任何布局读取。
6. **身份键带签名缓存**：`currentSrc + duration` 未变就直接复用旧 key，避免重复 `new URL()`；
   页面级 id（YouTube / B 站 URL 解析）也按 `location.href` 缓存。
7. **全屏宿主切换**：`fullscreenchange`（含 webkit / MS 前缀事件）时把 HUD 重新挂到全屏元素里，
   并把坐标基准换成该元素左上角——这是 B 站全屏看不到提示框的根因。
8. **HUD 外层只负责 `translate`、内层卡片只负责出现动画**，避免 `transform` 冲突；
   显示期间用 `requestAnimationFrame` 跟随滚动 / 调整窗口重定位，隐藏后立刻 `cancelAnimationFrame`。
9. 样式全部带 `!important` 与 `vsh-` 前缀，避免被站点 CSS（`.card`、`.rate` 之类）污染。
10. 权限最小化：只有 `storage`，无网络请求、无跨站数据访问；已删除 `storage.session`、`tabs.onRemoved`
    等没人用的死代码，内容脚本也不再处理弹窗用不到的 `setAll` / `forget` 消息。

## 七、已知限制

| 限制 | 说明 |
|---|---|
| 画中画窗口上的提示框 | PiP 窗口是系统级窗口，网页内无法在上面绘制 HUD（此时速度仍会生效，可在弹窗 / 徽标看速度） |
| 站点把 `<video>` 自身 `requestFullscreen` | 这种全屏无法在其上叠加任何 DOM，HUD 会隐藏（速度仍生效）；B 站等“全屏播放器容器”的站点 v1.2.0 已正常显示 |
| 扩展页 / Chrome 应用商店 / PDF 查看器 / 新标签页 | Chrome 禁止注入内容脚本，弹窗里会提示“此页面不可注入” |
| `chrome://` 、`edge://` 页面 | 同上 |
| 加密 / DRM 播放器（Netflix、Disney+ 等） | 原生 `playbackRate` 通常被限制或被站点强制重置，扩展无法稳定生效 |
| 音频轨道替换（MediaSource 中途换源） | 身份键含时长，极端情况下同一集可能产生两条记忆条目 |
| 页面自身把 `playbackRate` 写回（少数播放器轮询） | 需要时把「接管方式」调成全局接管并刷新页面 |

## 八、想改默认值

改这三处（保持一致即可）：`content.js` 的 `DEFAULTS`、`background.js` 的 `DEFAULTS`、
`options.js` 的 `DEFAULTS`。例如把默认微调幅度改成 0.25：

```js
// content.js / background.js / options.js 三处的 DEFAULTS
step: 0.25,
```

已安装过扩展的话，记得在设置页里也调一次（旧的 `chrome.storage.sync` 设置不会自动更新）。
